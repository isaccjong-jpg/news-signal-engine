# 국제정세 신호 검증 엔진 (1단계 · 매매 연결 없음)

매시간 국제정세 뉴스 → LLM 사건 분류·영향 종목 판단 → 구글시트 기록 → 1/5/20 영업일 뒤 KOSPI 대비 초과수익 자동 측정.
목적은 2~3개월 뒤 **"사건 후 과소반응 구간에 알파가 있는가"** 판정. 투자 자문·자동매매 아님.

## 구조
| 파일 | 역할 |
|---|---|
| `news.py` | Google News RSS(한 34·영 23개 축: 거시·지정학·업종·원자재·제약·국내정책·실적) + 네이버 뉴스 API 18개 축. 2시간 창, 제목 해시 중복제거, 축별 라운드로빈 150건 |
| `classifier.py` | 1차 선별(저가 모델) → 본 판단(Anthropic/Gemini, 그림자 실행 가능) + 검증: 유니버스 밖 코드·형식오류·기존 사건 후속보도 제거 |
| `private/universe.json` | 판단 허용 종목 82개(제약·비철전선 포함)(비공개, push 제외). 공개본은 `universe.sample.json` |
| `private/prompt.txt` | 판단 원칙(비공개, push 제외) |
| `prices.py` | 네이버 일봉(종목·ETF·KOSPI 지수, 키 불필요) + S&P500(네이버 해외지수 API → 실패 시 Yahoo) + 신호 시점 스냅샷 |
| `measure.py` | 진입가·수익률·초과수익 계산(베타 조정 1차 지표 + 단순 지수 대비 초과), 사건 단위 요약 통계 |
| `baskets.json` | 섹터 고정 바구니 18개(ETF 1 + 대표 종목 2~3). 사건 영향종목의 섹터마다 바구니 전체를 같은 시점에 기록 |
| `sheets.py` | 판정 시트 탭 자동 생성(신호로그/측정/바구니/요약/실행로그/_state) + 원문 보관 시트(`ARCHIVE_SHEET_ID`, 월별 탭 `원문_YYYY-MM`) |
| `main.py` | `auto`(크론) · `collect` · `measure` · `--dry-run` · `--mock-llm` |

## 비용 구조
- **실측 집계:** 매 실행 LLM 토큰(입력/출력)과 가격표(`PRICES_PER_MTOK`, 2026-10 공식: Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.1/$0.5 per MTok) 기준 추정비용을 `실행로그` 마지막 열과 `_state.usage_YYYY-MM`에 누적. 18시 일일요약 텔레그램에 "이달 누적 → 월말 추정 / 예산(`API_MONTHLY_BUDGET_USD`, 기본 100)" 표시, 80% 초과 전망 시 경고.
- **호출 조건:** 새 헤드라인(해시 미등록)이 1건 이상일 때만. 조용한 시간대 = 비용 0.
- **1차 선별(`SCREENER_PROVIDER`, 기본 gemini 무료):** 시장 무관 뉴스 제거 후 본 판단 모델로 전달. 재현율 우선(애매하면 남김). 실측 입력 150건 중 대부분이 연예·지역·논평이라 본 판단 입력 토큰 70~90% 절감 예상. 선별 결과 0건이면 본 판단 호출 생략. 선별 실패 시 전체 통과(fail-open) — 비용은 들어도 신호를 놓치지 않는 쪽.
- **선별 모델도 버전 해시에 포함.** 선별기가 본 판단의 재현율 상한을 정하므로 바꾸면 새 실험. `실행로그.수집뉴스`에 `150→12` 형태로 통과율 기록 — 이 비율이 5% 미만으로 떨어지면 선별기가 과하게 거르는지 원문 탭에서 표본 점검.
- **프롬프트 캐시는 사용하지 않음(의도적):** 캐시 유효시간(기본 5분)이 실행 주기(1시간)보다 짧아 매번 캐시 미스 + 캐시 기록 비용만 추가됨. 호출 간격이 5분 이내로 좁아지는 구조가 아니면 손해.

## 공개 저장소 보안 구조
- 공개되는 것: 수집·측정 뼈대 코드(범용, 엣지 없음).
- 비공개: 판단 원칙·유니버스(Secret), 결과(구글시트), 알림(텔레그램), API 키.
- 공개 로그에는 건수만 출력. 키·토큰 가림, LLM 출력 원문은 오류 메시지에도 미출력.
- 실제 매매 로직(2단계 이후)은 이 저장소에 넣지 않는다 — 증권 키가 걸리므로 별도 비공개 환경.

## 측정 규칙 (미래정보 차단)
- **기준가** = 판단 후 실제 체결 가능한 첫 종가. 영업일 15:20 이전 판단 → 당일 종가, 이후·휴장일 → 다음 영업일 종가.
- **판단→기준%** = 판단 시점 확정 종가 → 기준가. 판단 후 진입 전에 이미 움직인 폭(속도 경쟁에서 놓친 몫).
- **+1d/5d/20d** = 기준일부터 N 영업일 뒤 종가. 벤치마크는 아래 베타 조정/자산 ETF 규칙.
- **방향보정** = (종목% − 벤치%) × 방향(+1/−1). 양수면 적중.
- **요약 탭**: 사건 단위 평균(같은 사건의 종목 여러 개 → 1개 표본) + **ISO주 클러스터 표준오차**로 t값 계산(같은 주의 사건·겹치는 5일 구간은 독립이 아님). `주클러스터수` 열 = 표본이 퍼져 있는 주 수. **버전별로 따로 집계**.
- **기준선 행**: LLM 대신 "판단→기준 구간에 움직인 방향을 그대로 추종"한 결과. LLM이 이걸 못 이기면 해석의 부가가치 없음.
- **베타 조정**: 주식 벤치 = β×KOSPI, β는 기준일 직전 120영업일로 추정(0~2.5 클립, 미래정보 없음). 2026년 KOSPI는 반도체 쏠림으로 비반도체 β가 0.0~0.7까지 떨어져 있어 β=1 가정은 큰 왜곡.
- **자산 ETF**(금·원유·달러·채권·인버스)는 KOSPI 대비도, 절대수익도 아닌 **그 자산의 직전 120일 평균 드리프트 대비**로 측정(절대수익은 추세장에서 전부 적중으로 나오므로).
- LLM에는 유니버스 각 종목의 **최근 5/20영업일 수익률**을 함께 제공 — "이미 반영된 사건인지" 판단 근거(과소반응 가설의 핵심 입력). 하루 1회 측정 시 스냅샷.
- 측정은 하루 1회 KST 18시(장 마감 확정 후).

## 신호 시점 스냅샷·섹터 바구니·단순 초과 (2026-10-20 추가)
- **신호 시점 가격**: 판단 직후 `측정` 탭에 `신호시점가`(종목 현재가 — 장중이면 장중가, 장외면 직전 종가), `KOSPI@신호`, `SPX@신호`(S&P500, 미국 현지 최신 종가/장중가)를 같은 실행에서 기록. 이 값은 참고용이며 수익률 계산의 기준가는 위 "측정 규칙"의 **기준가(체결 가능한 첫 종가)** 그대로.
- **섹터 바구니** (`바구니` 탭): 사건의 영향종목이 속한 섹터마다 `baskets.json`의 고정 바구니(ETF 1 + 대표 2~3)를 전부 같은 시점에 기록. 방향은 그 섹터 영향종목 방향의 다수결. LLM이 고른 종목이 아니라 **섹터 전체가 움직였는지**를 보는 용도(종목 선택 효과와 섹터 효과 분리).
- **단순 초과수익** = 종목 N일% − 지수 N일%. 지수는 KOSPI(`단순초과K`/`초과K`)와 S&P500(`단순초과S`/`초과S`) 둘 다. S&P500은 KRX 일자 D의 종가 시점에 이미 확정된 미국 종가(현지일 < D)끼리 비교(미래정보 없음). `요약` 탭에 `참고:영향종목 KOSPI단순초과`, `참고:섹터바구니 KOSPI단순초과` 행으로 집계.
- **판정 1차 지표는 변경 없음**(베타 조정 5d 방향보정). 단순 초과는 β=1 가정이라 2026년처럼 반도체 쏠림 장에서 비반도체 종목의 초과가 체계적으로 왜곡되므로 참고 지표로 둔다. 두 지표가 반대 결론이면 그 자체가 보고 대상.
- 매매 연결 없음 — 이 저장소에는 주문·계좌 코드가 없고 2단계 전까지 추가하지 않는다.

## DART 기업행동 공시 신호 (H9 표본 외 추적, 버전 `dart-v1`, 2026-10-21 추가)
- 백테스트(`../event_backtest`, 2015~2026, 공시 31,449건)에서 **유일하게 사전 등록 기준을 통과**한 가설: 자사주 취득 공시 뒤 20일 β조정 초과 +1.3%(직접, t=2.5)·+1.5%(신탁, t=3.6), 유상증자·CB·자사주처분 공시 뒤 60일 −3~−6%(t 4~11), 무상증자는 5일 반등 뒤 60일 −7%. 같은 종목·같은 사전 하락폭의 비사건일 대조군은 −0.5%라 단순 반등이 아님.
- 엔진은 매일 18시 당일 접수 공시를 `신호로그`·`측정`에 기록만 한다(방향: 자사주 +, 증자·CB·처분·무상증자 −). 측정은 기존 경로(다음 거래일 종가 진입, 1/5/20d). LLM 호출 없음, 비용 0. `DART_API_KEY` 필요.
- **판정(2027-01-15, H1과 동시):** `요약` 탭 `dart-v1` `전체` 행 20d 방향보정 평균 > +0.4%, t > 2. 백테스트와 부호·크기가 맞으면 2단계 후보. 주의: 효과가 우측 꼬리(중앙값 ≈ 0)에서 나오므로 분산(동시 30~50 종목)이 전제이고, 직접 매입은 2025~26년에 약해졌다(신탁은 유지).

## 벡터 유사사건 백테스트 (`../analog_backtest`, 별도 폴더 — 이 엔진과 무관)
- 목적: 실시간 검증(2~3개월 대기)을 기다리지 않고, 과거 사건 헤드라인 → 당시 실제 반응으로 "유사 사건의 과거 반응을 따라가면 기준선을 이기는가"를 먼저 본다.
- 과거 뉴스 소스: **Google News RSS의 `after:`/`before:` 날짜 연산자**(한국어 `hl=ko` 포함, 질의·월별로 최대 ~100건). GDELT DOC API는 5초당 1회 제한이 엄격해 보조로만. 네이버 뉴스 API는 날짜 범위 검색이 없어 과거 수집 불가. 엔진 자체의 `원문_YYYY-MM` 탭은 2026-10-19부터 쌓이는 전방 아카이브.
- 규칙: LLM 판단 금지(결과를 학습으로 알고 있음) — 임베딩·가격만 사용. 시점 엄수(walk-forward: 평가 사건 이전 사건만 이웃 후보). 비교 대상 = 반응방향추종 기준선.

## 배포 — 한 줄 (gh CLI 있을 때)
`private/config.local.json`에 API 키 2개(`여기에_` 자리) 입력 → PowerShell에서 `.\deploy.ps1`.
저장소 생성·push·Secret 3개·첫 실행까지 자동. 시트 2개는 이미 생성·공유됨(판정 `1eauZi…`, 원문 `1C8qWS…`). gh가 없으면 아래 수동 절차.

## 배포 — 수동 (최초 1회, 약 10분)
1. GitHub에서 **공개(Public)** 저장소 `news-signal-engine` 생성 → 이 폴더 내용 push
   (공개 저장소 Actions 분은 무료·무제한, 인허가 엔진의 비공개 2,000분 한도와 무관. 키는 Secret이라 비공개 유지, 로그엔 키 가림 처리됨)
   ```powershell
   cd "$env:USERPROFILE\OneDrive\바탕 화면\WORK\news_signal_engine"
   mkdir .github\workflows -Force; Move-Item signal.yml,keepalive.yml .github\workflows\
   git init; git add .; git commit -m "init"; git branch -M main
   git remote add origin https://github.com/isaccjong-jpg/news-signal-engine.git
   git push -u origin main
   ```
2. 구글시트 **2개** 새로 만들기(판정용, 원문 보관용) → 둘 다 서비스계정 이메일(`client_email`)을 **편집자**로 공유. 탭은 첫 실행 때 자동 생성. 원문은 하루 ~3,600행이라 분리해야 판정 시트가 느려지지 않음.
3. 저장소 Settings → Secrets → Actions → 3개 등록
   - `CONFIG_JSON`: `config.example.json` 형식(`GCP_SA_JSON`에 서비스계정 JSON 통째로)
   - `PRIVATE_PROMPT`: `private/prompt.txt` 내용 그대로 붙여넣기 (판단 원칙 = 전략 핵심)
   - `PRIVATE_UNIVERSE`: `private/universe.json` 내용 그대로 붙여넣기
   - `private/` 폴더는 `.gitignore`로 push 제외. 두 Secret이 없으면 Actions 실행이 **중단**됨(기본값으로 돌아 데이터 오염되는 것 방지)
4. Actions 탭 → news-signal-engine → Run workflow (`collect`) 1회 수동 실행 → 시트 `실행로그` 확인.
5. 이후 매시 7분 자동. 18시 실행분에서 측정·요약 갱신.

## 가설 계층(무엇을 검증하는지 혼동 금지)
- **전제(검증 불가, 공리로 둠):** "경제는 심리다" — 가격은 펀더멘털만이 아니라 참여자 심리로 움직인다.
- **이 엔진이 검증하는 좁은 가설(H1):** "LLM이 매시간 헤드라인을 읽고 낸 방향 판단이, 시초가 갭 이후 5영업일 동안, 베타 조정 초과수익을 비용(0.4%) 이상으로, 단순 반응추종보다 잘 낸다."
- H1이 기각돼도 전제는 기각되지 않는다. 전제의 다른 조작화(H2 투자자별 수급 극단 → 반전, H3 공포지수/검색량 극단 → 지수 반전 등)는 같은 측정 인프라로 별도 검증한다. **한 조작화의 실패를 전제의 실패로, 한 조작화의 성공을 전제의 증명으로 읽지 않는다.**

## 사전 등록(판정 기준을 미리 고정 — 결과 보고 기준을 바꾸지 않기 위해)
- **1차 지표(이것만으로 판정):** `요약` 탭 `전체` 행의 **5d 방향보정 평균·t값**. **양측 검정.**
  - **과소반응 통과(추종 전략):** 사건 N≥60 **이고** `주클러스터수`≥8(한 위기 주간에 몰린 표본 금지) **이고** 평균 > +0.4%(왕복 비용: 2026 코스피 거래세 0.20%+수수료+슬리피지) **이고** t > +2 **이고** 기준선 행 평균보다 높음.
  - **과잉반응 통과(역추종 전략):** 같은 N·주수 조건 **이고** 평균 < −0.4% **이고** t < −2. LLM 판단의 반대로 가면 돈이 되는 경우 — "경제는 심리다" 전제에서는 과잉반응도 똑같이 유효한 결과이므로 미리 등록해 둔다(결과를 보고 "사실 반대로 하면 됐다"고 끼워 맞추는 것 금지).
  - 둘 다 아니면 기각. |t|<2 구간은 "모름"이 아니라 "이 조작화로는 알파 없음"으로 읽는다.
- **2차 지표(참고):** 20d, 1d. 1d는 갭에 먹힌 몫이 커서 통과해도 실행 불가할 수 있음.
- **탐색용(판정에 쓰지 않음):** 분류별·확신도별 행. 그룹이 많아 하나쯤은 우연히 t>2가 나온다(다중비교). 여기서 좋은 그룹을 골라 "이 분류만 하면 된다"고 결론내는 것 금지. 가설로 삼아 **다음 기간에 1차 지표로 재검증**만 허용.
- **버전 = 판단원칙 + 유니버스 + 모델ID + temperature 해시.** 하나라도 바뀌면 새 실험이며 요약 탭이 버전별로 자동 분리된다. 모델ID는 **날짜 고정 스냅샷 ID**로 지정할 것(같은 이름도 업데이트되면 다른 모델).
- **재채점 규칙(미래정보 오염 방지):** 보관한 원문을 새 프롬프트로 재채점하는 것은 **학습 컷오프가 해당 뉴스 기간보다 앞선 모델**로만 허용. 컷오프가 그 기간을 지난 신모델은 결과를 이미 알고 있을 수 있으므로 재채점 결과를 판정에 쓰지 않는다.
- **그림자 실행:** `LLM_PROVIDERS="anthropic,gemini"`처럼 두면 같은 뉴스를 두 모델이 판단하고 각자 버전으로 기록(알림은 첫 모델만). 전체 기간을 같은 표본으로 비교할 수 있어 2~3주 단기비교보다 정확.
- 통과해도 "한 국면(2~3개월)에서 통과"일 뿐. 2단계는 소액 모의부터.
- **2차 사전 등록(2026-10-20 추가, 판정 보조):**
  - **분류 3묶음** — ① 거시·지정학(지정학_전쟁·제재, 무역_관세, 통화정책, 중국_정책, 북한, 정치_선거) ② 업종·원자재(원자재_에너지·금속농산물, 공급망_기술통제, 산업_업황수주, 국내정책_규제) ③ 기업(기업_실적, 제약바이오_임상허가, 소송_특허). 묶음별로 1차 지표와 같은 조건을 적용하되 다중비교(3개) 보정으로 **|t| > 2.4**. 통과 묶음만 2단계 대상으로 삼을 수 있다. 묶음 밖의 세부 분류 선택은 금지.
  - **지연 비용** — 기업 묶음의 `판단→기준%` 절대값 평균이 다른 묶음의 2배 이상이면 "매시간 수집으로는 늦다"로 기록하고, 2단계에서 그 묶음은 제외하거나 수집 주기를 줄인 뒤 재검증.
  - **5일째 손실 신호의 5d→20d 추가수익** — 방향보정5d < 0인 종목행의 (방향보정20d − 방향보정5d) 평균. 양수·t>2면 "손절보다 보유" 근거, 음수면 "5일 후 청산" 유지. 2단계 청산 규칙의 입력.
  - **베타 조정 vs 단순 초과 불일치** — 두 1차 지표(전체 5d)의 부호가 다르면 통과로 보지 않고 원인(시장 β 쏠림)을 보고서에 적는다.

## 알려진 한계(과해석 방지)
- 일봉만 사용: 장중 판단의 '판단→기준%'에는 판단 이전 장중 움직임도 섞임. 국제 뉴스는 대부분 야간이라 영향 제한적.
- 베타는 직전 120일 추정치라 사건 직후 베타가 급변하면 벤치가 어긋남. 5d를 1차로 두는 이유 중 하나.
- 주 클러스터로 사건 간 상관을 처리하지만, 몇 주에 걸친 거대 사건(전면전 등)은 주 경계를 넘어 상관됨 → 그 기간 t값은 보수적으로 해석.
- LLM은 과거 사례의 시장 반응을 학습으로 알고 있으나, 전방 검증(미래 사건)이므로 미래정보 혼입은 없음. 단 모델 교체도 '새 실험'으로 취급.
